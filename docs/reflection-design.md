# 振り返りシステム 設計メモ

## 0. 目的

「日記を書く」ことではなく、**自分を知り → 強みを活かし → 弱みを改善する**ための
データを継続的に貯めることが目的。そのために3つの原則を置く。

1. **毎回おなじ軸で聞く** — 比較できないログは分析できない。質問は固定、答えは自由。
2. **ログと結論を分ける** — 生の記録（振り返りログ）と、そこから抽出した自己理解
   （自己理解台帳）を別DBにする。台帳こそが最終成果物で、ログはその根拠。
3. **記録は飛ぶ前提で組む** — 歩くのは平日だけ、答えられない日もある。
   欠損が混ざっても壊れない集計にし、途切れたことを咎めない。

```
日次(3分/平日) ─┐
週次(15分) ─────┼─→ 振り返りログDB ──抽出──→ 自己理解台帳DB
月次(30分) ─────┤                            （強み/弱み/価値観の仮説と検証状態）
四半期(60分)────┘                                      │
                        目標DB ←──レビュー──────────────┘
                （人生目標 / 中長期目標 / 短期目標）
```

## 1. 日次（平日の夜の散歩・約3分・音声）

毎回おなじ5問。散歩しながら口頭で答えられる長さに抑える。

| # | 質問 | これで何を取るか |
|---|------|-----------------|
| 1 | 今日いちばんエネルギーが上がった瞬間は？ | 強み・情熱の在りか（何をしている時の自分が強いか） |
| 2 | 逆に、いちばん消耗した・気が重かった瞬間は？ | 消耗源・弱みのトリガー |
| 3 | 今日の自分の判断や動きで「これは自分らしい」と思えたことは？ | 強みの発露（無自覚に出ている癖＝才能の候補） |
| 4 | うまくいかなかったこと。なぜそうなったと思う？ | 失敗のパターン。「なぜ」まで一言添えるのが肝 |
| 5 | コンディション：エネルギー / 集中 / 気分（各1〜5） | 数値。後から相関を見る唯一の定量軸 |

- 1〜4は各1〜2文でよい。言い淀んでもそのまま記録する（取り繕わない）。
- 最後にClaude側で**キーワードを3つ**自動抽出してタグ化する（人・場所・活動・感情）。
- 答えられない日は「パス」でよい。空欄で記録し、継続を優先する。
- 日次では**目標に触れない**。毎日問うと目標が義務になる。

### 日次で聞かないこと（意図的に外したもの）
- ToDoの消化率 → タスク管理の仕事であり、自己理解には効かない
- 感謝リスト → 効果はあるが定型化しやすく、5問を圧迫する（週次に回す）
- 長期目標の進捗 → 日次で問うと焦りを生む。週次以降で扱う

## 2. 記録が飛ぶ前提での設計

歩くのは基本的に平日のみ。歩かない日・答えられない日がある。
これを例外扱いせず、最初から仕様に織り込む。

| 論点 | 決めたこと |
|------|-----------|
| 対象日 | 記録した日時ではなく**振り返る対象の日**を持つ。深夜0時以降の記録は前日扱い |
| まとめ記録 | 複数日をまとめて話した場合も、日ごとに別ページを作る（1ページに混ぜない） |
| 遡り | こちらから未記録日を掘り起こさない。本人が言い出したときだけ |
| 集計の母数 | 記録がある日だけ。欠損日を0や平均値で埋めない |
| 記録日数 | 週次以降に事実として記録するだけ。少なさに言及しない |
| ストリーク | **追わない。** 連続記録を評価軸にすると、途切れた時点でやめたくなる |
| 日次0件の週 | 週次は実施する。要約提示を省き、記憶ベースで3問に絞る |

## 3. 週次（日曜夜・約15分）

日次ログをClaudeが読み込み、**まず要約と気づきを提示してから**問いかける。
ゼロから思い出すのではなく、提示された材料に反応する形にするのが継続のコツ。

1. （Claude提示）今週の日次ログの要約・繰り返し出たテーマ・数値の推移（記録がある日のみ）
2. この要約、当たってる？違和感があるのはどこ？
3. 今週いちばん手応えがあった場面と、そこで効いた自分の強みは？
4. 今週いちばん引っかかった場面。同じことは前にもあった？（＝パターンか単発か）
5. 先週立てた「実験」の結果は？（やった/やらなかった、何が起きたか）
6. **短期目標のレビュー**：近づいた？次の一手は？（最大3件）
7. 来週ひとつだけ試す「実験」を決める
8. 今週の自己評価（1〜5）と、その理由を一言

→ **週次のアウトプット**：自己理解台帳への追記・更新を1〜3件、短期目標の更新。

## 4. 月次（月末・約30分）

1. （Claude提示）4週分の実験の結果一覧と、台帳の更新履歴
2. 今月の自分を一言でいうと？
3. 強み仮説の更新：効いた強み／思ったより効かなかった強み
4. 弱みの改善進捗：対策は機能した？別の手が要る？
5. **環境要因の棚卸し**：今月、自分が強かった条件と弱かった条件は何だったか
   （時間帯・人数・締切の有無・場所・体調）← 強みは「条件」とセットで初めて使える
6. **中長期目標のレビュー**：進み具合と、短期目標との整合
7. 来月のフォーカス（ひとつだけ）

## 5. 四半期（3ヶ月ごと・約60分）

1. （Claude提示）台帳の全項目と、この3ヶ月での状態遷移
2. 台帳の書き直し：確信に変わったもの／棄却するもの／表現を変えるもの
3. 価値観の確認：この3ヶ月で守れていた価値観・裏切っていた価値観
4. **人生目標のレビュー**：今も本心か。言い方を変えたくなっていないか
5. 中長期目標の取捨選択と、短期目標の再設定
6. 1年前の自分と比べて、明確に変わったことは？
7. 次の四半期のテーマを一文で

## 6. Notion データ構造

既存の「📓 日記」は自由記述の場としてそのまま残し、振り返りは
**🪞 SelfContexts** ページ配下の新規3DBで運用する。

### DB1: 🌙 振り返りログ

`data_source_id: 2923cd5a-9b5e-460a-99ff-e7d6484147aa`

| プロパティ | 型 | 備考 |
|-----------|-----|------|
| Name | title | `2026-09-16 (火) 日次` / `2026-W38 週次` |
| 種別 | select | 日次 / 週次 / 月次 / 四半期 |
| 対象日 | date | 週次以降は期間（開始〜終了） |
| エネルギー / 集中 / 気分 | number | 各1〜5（日次） |
| 自己評価 | number | 1〜5（週次以降） |
| 記録日数 | number | 週次以降。期間内に日次ログが何件あったか |
| キーワード | multi_select | Claudeが自動抽出（3つ程度） |
| 次の実験 | rich_text | 次の振り返りまでに試すこと |
| 実験の結果 | select | 未実施 / 実施 / 部分的 / 対象外 |
| 入力元 | select | 音声 / 手入力 / フォーム |
| 関連する自己理解 | relation → DB2 | この回で更新した自己理解 |
| レビューした目標 | relation → DB3 | この回でレビューした目標 |

ページ本文に Q&A をそのまま見出し付きで記録する（生の言葉を残すことが重要）。

### DB2: 🧭 自己理解台帳

`data_source_id: 5c29b421-d5cd-41ff-9094-6b01187cd108`

1行 = 自分についての仮説ひとつ。これが蓄積されていく資産。

| プロパティ | 型 | 備考 |
|-----------|-----|------|
| Name | title | 仮説を一文で（例:「初動の遅さは情報不足ではなく失敗予期から来る」） |
| 分類 | select | 強み / 弱み / 価値観 / エネルギー源 / 消耗源 / 思考のクセ / 環境条件 |
| 状態 | select | 仮説 / 検証中 / 確信あり / 更新済 / 棄却 |
| 確信度 | number | 1〜5 |
| 活かし方・対策 | rich_text | 強みなら使いどころ、弱みなら回避・補完策 |
| 次の実験 | rich_text | この仮説を検証する具体行動 |
| 根拠となる振り返り | relation → DB1 | 元になった振り返り（複数） |
| 関連する目標 | relation → DB3 | この自己理解が効く目標 |
| 初出 / 最終更新 | date / last_edited_time | |

更新は**週次以降のみ**。1日の出来事で仮説を立てると、その日の気分に引きずられる。
**棄却を残すのが要点**。「違った」という記録が自己理解の精度を上げる。

### DB3: 🎯 目標

`data_source_id: f3428b4c-f911-4771-9183-5f187439a31d`

| プロパティ | 型 | 備考 |
|-----------|-----|------|
| Name | title | 目標を一文で |
| 階層 | select | 人生目標 / 中長期目標 / 短期目標 |
| 状態 | select | 構想中 / 進行中 / 達成 / 見直し中 / 取り下げ |
| レビュー頻度 | select | 週次 / 月次 / 四半期 ← **どの振り返りで扱うかを決める** |
| なぜこれをやるのか | rich_text | 動機。迷ったときに立ち返る場所 |
| 達成の目安 | rich_text | どうなったら達成と言えるか |
| 期限 / 進捗 | date / number | 進捗は0〜100 |
| 次の一手 | rich_text | |
| 最終レビュー | date | レビューのたびに更新 |
| 親目標 / 子目標 | relation（自己参照） | 短期→中長期→人生 とぶら下げる |
| 関連する自己理解 | relation → DB2 | この目標に効く強み・立ちはだかる弱み |
| 関連する振り返り | relation → DB1 | |

**レビュー頻度プロパティが、目標と振り返りをつなぐ蝶番**になる。
短期目標は週次、中長期は月次、人生目標は四半期でしか触らない。
人生目標を毎週問うと疲れるし、短期目標を四半期にしか見ないと形骸化する。

**関連する自己理解のリレーション**が、この構成のもう一つの要。
「この目標が進まないのは、この弱みが効いているから」を構造として持てる。

## 7. 仕組み（どう「聞いてきてもらう」か）

入力方式は **スマホのClaudeアプリに音声で話す** を主軸にする。

```
平日 21:30  Routineが発火 → 通知「今日の振り返り、いきますか？」
  ↓
散歩しながら Claude に音声で応答（1問ずつ返ってくる）
  ↓
5問終了 → Claudeがキーワード抽出・数値整形
  ↓
Notion MCP で 振り返りログDB に1ページ作成
  ↓
（週次以降）過去ログを読み込んで要約 → 対話 → 台帳DB・目標DBを更新
```

### 構成要素

| 要素 | 置き場所 | 役割 |
|------|---------|------|
| `.claude/skills/reflection/questions.yaml` | このリポジトリ | 4種類の質問セット（唯一の正） |
| `.claude/skills/reflection/SKILL.md` | 同上 | 聞き方・欠損の扱い・Notion書き込み手順 |
| Routine（定期実行） | Claude Code Remote | 平日夜・日曜夜・月初・四半期初に起動 |
| Notion 3DB | 🪞 SelfContexts 配下 | 保存先 |

質問文はすべて `questions.yaml` に集約し、運用しながら育てる。
「この質問、答えにくい」と思ったらそのファイルだけ直せばよい状態にする。

## 9. 定期実行（Routine）

| Routine | スケジュール（JST） | trigger_id |
|---------|-------------------|-----------|
| 🌙 日次の振り返り | 平日 21:30 | `trig_01T71AByxKHjPZ3nMNprSdpV` |
| 📘 週次の振り返り | 日曜 20:00 | `trig_01BU8oYbyJA3kxXj2wQgHieu` |
| 📙 月次の振り返り | 毎月1日 20:00 | `trig_01MxHzaePkdfemv9dWPBzqbz` |
| 📕 四半期の振り返り | 1/4/7/10月の2日 20:00 | `trig_01CuWBEpoMBivMnG3gFaB2VL` |

いずれも発火のたびに新しいセッションを作り、プッシュ通知を出す。

### 既知の制約（要対応）

Routine を CLI から作成すると **Notionコネクタが引き継がれない**。
このままでは発火したセッションが Notion に書き込めない。

対応：claude.ai の Routines 画面で各Routineを開き、Notionコネクタを有効にする。
（またはRoutines画面から作り直す。プロンプトは上記のtrigger_idから確認できる）

### 前提

Routineが作るセッションは既定ブランチをクローンするため、
`.claude/skills/reflection/` が main に入っていないとスキルが読まれない。
各Routineのプロンプトにはフォールバックとして手順とDB IDを直書きしてあるので
未マージでも動作はするが、**main へのマージ後が本来の状態**。
