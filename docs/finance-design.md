# 家計BS/PL 設計メモ

## 0. 目的

家計簿をつけることが目的ではない。人生目標「何かに縛られて働く必要がない状態」に対して、
**今どこにいて、あと何年かかるか**を数字で出すための計器をつくる。

短期目標「資産と生活費の現在地を数字で把握する」の実行手段でもある。

## 1. 扱わないもの

**銀行・証券・カードの認証情報は一切扱わない。**
技術的にできないという話ではなく、やってはいけない。会話に認証情報が残るうえ、各社の規約にも反する。
口座への接続はマネーフォワード側の仕事とし、こちらはエクスポートされたCSVだけを扱う。

## 2. データの流れ

```
各金融機関 ──→ マネーフォワードME（口座連携はMFが担当）
                      │ CSVエクスポート（本人・月1回）
                      ↓
                Googleドライブ
                      │ aggregate.py（決定的に計算する）
                      ↓
        📈 家計サマリー（月次）DB
```

**明細はNotionに入れない。** 月に数百行あり、入れるとDBが重くなる。
振り返りで見たいのは推移と指標であって個別の取引ではないため、明細はドライブのCSVに残す。

## 3. Notion DB

### 📈 家計サマリー（月次）

`data_source_id: afde1ecc-1729-49ad-9a17-a3a7f39d7490`

1行 = 1ヶ月。PL（期間）とBS（月末時点）を同じ行に持つ。

| 区分 | プロパティ |
|------|-----------|
| 収入 | 給与 / 賞与 / 配当 / 家賃収入 / その他収入 / 収入合計 |
| 支出 | 住居費 / 水道光熱費 / 通信費 / 保険 / 教育費 / 食費 / 日用品 / 交通費 / 娯楽・交際費 / 税・社会保険 / その他支出 / 支出合計 |
| 収支 | 収支 / 貯蓄率 |
| 資産 | 現金預金 / 証券 / 年金資産 / 不動産評価額 / その他資産 / 資産合計 |
| 負債 | 住宅ローン残高 / その他ローン / カード未払 / 負債合計 |
| 指標 | 純資産 / 不労所得 / **不労所得カバー率** / **到達予測年** |
| 管理 | 対象月 / データ元 / メモ |

合計や比率は **Notionの数式ではなく、書き込み時に計算した値を入れる**。
数式は空欄の扱いでつまずきやすく、値が見えないとデータの持ち出しもしにくいため。
手で値を直したときは合計も直す必要がある。

## 4. 見るべき3つの指標

| 指標 | 定義 | 意味 |
|------|------|------|
| 貯蓄率 | 収支 ÷ 収入合計 | 到達スピードを決める |
| **不労所得カバー率** | (配当+家賃収入) ÷ 支出合計 | **100%になった月が「何かに縛られて働く必要がなくなった」日** |
| **到達予測年** | 試算値 | 今のペースでカバー率100%に届く年 |

到達予測年が最も重要。目標は2049年3月なので、予測年がそれより手前なら余裕があり、
後ろなら軌道修正の材料になる。**単月で一喜一憂せず、四半期で3ヶ月分を並べて傾向を見る。**

## 5. スクリプト

### `aggregate.py` — MF CSV → 月次集計

数百行の合計をLLMが目で計算すると誤りが出るため、決定的に動くコードにしてある。

処理の要点：

- 文字コードは `utf-8-sig` → `cp932` → `utf-8` の順で判定（MFはShift-JISで出すことがある）
- `計算対象 != 1` の行を除外（本人が集計対象外にしたもの）
- **`振替 == 1` の行を除外** — 自分の口座間の移動は収入でも支出でもない
- **大項目「現金・カード」を除外** — ATM出金やカード引落を支出に数えると二重計上になる
  （出金と、そのお金で買った物の両方を数えてしまう）
- 金額の符号で収入／支出を判定する（大項目の分類より符号を優先）
- **未知の大項目は黙って「その他」に寄せず、警告として返す**
  寄せてしまうと支出の中身が見えなくなり、要因分析ができなくなる

### `projection.py` — 経済的自立までの年数

`必要金融資産 = (年間支出 − 年間家賃収入) ÷ 取り崩し率` に、現在の金融資産と年間貯蓄を
複利で積み上げて到達年を出す。家賃収入は資産を取り崩さずに得られるので、その分だけ必要額が下がる。

前提はすべてコマンドライン引数で見えるようにしてある（既定：利回り5%、取り崩し率4%）。

**この数字の限界を必ず添えること：**

- 取り崩し率4%は米国株の過去データに基づく経験則。日本の税制・為替・年金を織り込んでいない
- 運用益・配当への課税（約20%）を引いていないため、楽観側に出る
- 将来の支出変化（子の独立、医療費の増加）を含んでいない
- 精度を競う数字ではなく、**今のペースが目標に対して速いか遅いかを見るための計器**

## 6. 自動では取れないもの

| 項目 | 取得方法 | 更新頻度 |
|------|---------|---------|
| 現金預金 / 証券 / 年金資産 | MFの「資産」画面から転記 | 月1回 |
| 不動産評価額 | 査定サイトの概算 | 年1回 |
| 住宅ローン残高 | 返済予定表 | 年1回 |

不動産とローンは前月値を引き継ぎ、1年以上更新がなければその旨を添えるだけにする。

## 7. 数字を出したあとの態度

振り返りスキルと同じく、**評価しない。**

- 「支出が多い」「もっと節約できる」と言わない。求められたときだけ答える
- 前月比が悪化していても、それ自体を問題として指摘しない
- 数字が悪い月ほど、背景（特別な支出、収入の端境期）を先に聞く

家計の数字は自己評価に直結する。責められる場所になった時点で、記録は止まる。
止まった家計簿からは何も分からないので、続くことが正確さより優先する。

## 8. Routineと実行順序

家計の集計を月初に走らせると、**カードの利用確定が間に合わず数字が欠ける**。
そのため実行日をずらし、家計 → 月次 → 四半期 の順に並べてある。

| Routine | 日（JST） | trigger_id |
|---------|----------|-----------|
| 📈 家計の月次集計 | 毎月8日 20:00 | `trig_01KZbsCyf7BoJLV1HvvdwziE` |
| 📙 月次の振り返り | 毎月10日 20:00 | `trig_01MxHzaePkdfemv9dWPBzqbz` |
| 📕 四半期の振り返り | 1/4/7/10月の11日 20:00 | `trig_01CuWBEpoMBivMnG3gFaB2VL` |

月次の振り返りは家計サマリーを読み、💰の目標レビューのときに3指標を事実として提示する。

### 要対応

📈 家計の月次集計 Routine には **Notion と Google ドライブの両方**のコネクタが要る。
CLIからは付与できないため、claude.ai の Routines 画面で設定する（手順は
`docs/reflection-design.md` の「既知の制約（Notionコネクタ）」と同じ）。
