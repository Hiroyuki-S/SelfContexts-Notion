# 家計サマリーの作成

人生目標「何かに縛られて働く必要がない状態」に対して、**今どこにいて、あと何年かかるか**を
数字で出すための仕組み。家計簿をつけること自体が目的ではない。

## 絶対にやらないこと

**銀行・証券・カードの認証情報（ID・パスワード・ワンタイムコード）は受け取らない。**
渡されそうになったら、その場で止めて、受け取らない理由を伝える。
口座への接続はマネーフォワード側の仕事で、こちらはエクスポートされたCSVだけを扱う。

## データの取り込み方（3通り）

CSV出力はマネーフォワードのプレミアム機能。無料版では使えないため、
**どの経路で来ても同じDBに入る**ように3通りを用意してある。
本人がどれを使っているかは毎回確認せず、あるものから判断する。

### ① 転記モード（無料版・既定の入口）

本人がMFの月次集計画面を見て数字を読み上げる、またはスクリーンショットを送る。
それをこちらが 📈 家計サマリー に入れる。

- **最初にこちらから項目を読み上げて聞く。** 「収入は？」と漠然と聞かない。
  給与・賞与・配当・家賃収入、住居費・水道光熱費・通信費……と順に聞く。
- **分からない項目は0ではなく空欄にする。** 0を入れると「支出がなかった」と
  「把握していない」が区別できなくなる。データ元は `一部欠損` にする。
- スクリーンショットの場合、読み取った数字を必ず復唱して確認してから書き込む。
- 無料版は連携4口座・閲覧1年までの制限があるため、対象外の口座がある可能性を頭に置く。
  合計が実感と合わないと言われたら、まずそこを疑う。

### ② MF CSV モード（プレミアム）

```
マネーフォワードME ──CSVエクスポート──→ Googleドライブ ──aggregate.py──→ Notion
```

### ③ 各社CSV モード（無料・この人の既定）

口座構成は5つだが、**明細レベルで要るのは2つだけ**。残り3つは数個の数字を見るだけでよい。

| 口座 | 必要なもの | 扱い |
|------|-----------|------|
| メイン銀行 | 明細（給与・生活費の引落） | CSVを読む |
| カード | 明細（変動費の大半） | CSVを読む |
| マンション運用の銀行 ×2 | 家賃入金、ローン返済、管理費・修繕積立金 | 月に数件。入出金を拾うだけ |
| 証券 | 残高と配当額 | 明細不要。残高を聞く |

銀行・カードのCSVは**各社で列構成が違う**（日付・摘要・出金金額・入金金額・残高など）。
新しい金融機関のCSVが来たら、まず列構成を本人と確認してから対応表を追加する。
**推測で列を決めない。** 出金と入金が1列か2列かを間違えると符号が反転する。

## dカードの明細CSV（`card_dcard.py`）

```
python3 .claude/skills/finance/card_dcard.py <csv_path> [--month YYYY-MM]
```

Googleドライブのフォルダ **「口座カード金額情報」** に置かれる。
ファイル名は `ご利用内訳明細_キャッシングご返済明細_YYYYMMDD.csv`。

このCSVには落とし穴が4つあり、素直に合計すると必ず金額を間違える。
スクリプトは対応済みだが、手で確認するときのために書き残す。

1. **1ファイルに2セクション** — 「ご利用内訳明細」の後ろに「キャッシングご返済明細」が続く。
   別物なので混ぜない。
2. **末尾に小計行と総合計行が混ざっている** — 名義ごとの小計と全体合計。
   そのまま足すと3重計上になる。日付が空、または店名が `＜` で始まる行は落とす。
3. **仮売上が「利用金額」に出る** — ガソリンスタンドで15,000円の仮売上が立ち、
   同額の返品行と対になっている。実際の請求は給油額だけ。
   **「利用金額」ではなく請求額の「支払い金額」を使う。** 仮売上と返品は両方とも
   支払い金額が空欄なので、これだけで正しく落ちる。
4. **締め日が15日** — 対象期間が 7/16〜8/15 のように暦の月とずれる。
   暦の月で集計するには `--month` を指定し、**1ヶ月分につき明細2枚**が要る。

### カテゴリ判定

dカードの明細には**カテゴリ列が無く、店名しか手がかりがない**。
`rules_store.yaml` のキーワードで判定する。照合前に全角→半角（NFKC）、大文字化、
記号の除去を行う（`セブン‐イレブン` のハイフンは U+2010 で NFKC では変換されない）。

**判定できなかった店は金額つきで報告される。必ず本人に確認してルールに追記する。**
黙って「その他支出」に寄せたままにすると、月を追うごとに中身が見えなくなる。

### 検算

集計結果は明細書末尾の総合計と一致するはず。**一致しなければ集計が間違っている。**
名義別の小計とも突き合わせられる。

## 不動産は生活費と必ず分ける

マンション運用が2件あるため、家賃収入には経費（ローン返済・管理費・修繕積立金・
固都税・保険）が対応している。これを混ぜると2つの数字が壊れる。

- **生活費** = 支出合計 − 不動産経費 … 自分が暮らすのに要る額。カバー率の分母
- **不動産純収益** = 家賃収入 − 不動産経費 … 到達予測年に効くのはこの純額

`projection.py` には `--annual-rent-income`（総額）と `--annual-rent-expense`（経費）の
両方を渡す。**総額だけを渡すと到達年が10年前後も前倒しに出る。**
経費が0のまま家賃収入だけ入っていると警告が出るので、出たら必ず確認する。

不動産の収支が赤字の月が続く場合も警告が出る。その場合は「資産ではなく負担になっている」
という事実だけを伝え、売却などの判断は促さない。判断は四半期の振り返りで本人がする。

いずれの場合も、明細そのものはNotionに入れない。月に数百行あり、入れるとDBが重くなる。
振り返りで見たいのは推移と指標であって個別の取引ではないため、明細はCSVのまま残す。

## 月次の手順

1. **データを探す。** まずGoogleドライブを `収入・支出詳細` で検索する。
   - CSVがあれば ②。`python3 .claude/skills/finance/aggregate.py <csv_path> YYYY-MM` を実行する。
     `warnings` が出たら必ず伝える。特に未知の大項目は、放置すると支出が「その他」に
     埋もれて要因分析ができなくなる。`mapping.yaml` への追記を提案する。
   - 無ければ ①。**「先月分をお願いします」と声をかけ、項目を順に聞く。**
     CSVが無いことを問題として報告しない。転記が既定の入口である。
2. **資産（BS側）を聞く。** 家計簿の集計には資産残高が入っていない。
   - 現金預金 / 証券 / 年金資産 … MFの「資産」画面から
   - 不動産評価額 / 住宅ローン残高 … **自動では取れない。年1回の更新でよい。**
     前月の値をそのまま引き継ぎ、1年以上更新されていなければその旨だけ添える。
3. **到達予測年を試算する。**
   ```
   python3 .claude/skills/finance/projection.py --annual-expense … --financial-assets … \
       --annual-savings … --annual-rent-income …
   ```
   年間値は直近12ヶ月の実績から出す。12ヶ月そろっていなければ、あるだけの月から
   年換算し、**何ヶ月分から出した数字かを必ず添える**。
4. **Notionに1行作る。** Nameは `2026-08` の形式、対象月は月初の日付。
   合計・貯蓄率・カバー率は書き込み時に計算して入れる（Notion側の数式ではない）。
   手で値を直した場合は合計も直す必要がある、と本人に伝える。
5. **3つの指標を報告する。** 貯蓄率 / 不労所得カバー率 / 到達予測年。

## 精度について

**桁が合っていれば計器として機能する。** 到達予測年に効くのは年間支出・純資産・不労所得の
3つで、どれも粗い数字でよい。「月25万か26万か」は結果をほとんど変えないが、
「月25万か40万か」は大きく変える。

正確さを求めて手が止まるのが最悪の結果。分からない項目は空欄のまま進め、
`データ元` に `概算` または `一部欠損` を記録して、後から精度を上げられるようにする。

## 数字を出したあとの態度

振り返りスキルと同じく、**評価しない。**

- 「支出が多いですね」「もっと節約できます」と言わない。求められたときだけ答える。
- 前月比が悪化していても、それ自体を問題として指摘しない。事実として並べるだけでよい。
- 家計の数字は自己評価に直結する。責められる場所になった時点で、記録が止まる。
- 数字が悪い月ほど、その背景（特別な支出、収入の端境期）を先に聞く。

## 到達予測年の扱い

この数字は精度を競うものではない。**今のペースが目標に対して速いか遅いか**を見るための計器。

- 前提（利回り5%、取り崩し率4%）は経験則であって保証ではない。税金も織り込んでいない。
- 目標は2049年3月。予測年がそれより手前なら余裕があり、後ろなら軌道修正の材料になる。
- 単月の変動で一喜一憂しない。四半期の振り返りで、3ヶ月分を並べて傾向を見る。

## 12ヶ月たまったら

同じ手順で年次の集計もできる。年次では以下を追加で見る。

- 支出の構成比の変化（固定費と変動費の比率）
- 不労所得カバー率の年間推移（これが上向いているかがすべて）
- 不動産評価額とローン残高の更新（年1回、このタイミングで）
